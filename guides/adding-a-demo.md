# 題材を追加する手順

[English](adding-a-demo.en.md)

ビルド手順は無い。ファイルを置いて `<script>` で読み込むだけ。既存の構成に合わせることで、題材が増えても迷わないようにする。

## 1. 構成の規約

```
<題材名>/
├── index.html      日本語
└── app.js          画面側（日英で共用する）
en/<題材名>/
└── index.html      英語
```

- **1 題 1 ディレクトリ。** ディレクトリ名がそのまま公開 URL になる。
- **ディレクトリ名は英小文字とハイフン**（`k-means`、`linear-transformation`）。日本語やアンダースコアは使わない。
- **日本語版を既定の場所、英語版を `en/` 以下の同じ階層**へ置く。URL の対応が崩れない。
- レッスンが複数ある題材は `pages/` に分け、共通の画面側を `app/` に置く（`linear-transformation` の形）。
- **公開済みの URL は変えない。** どうしても移す場合は、旧 URL に転送ページを残す（`k-means.html` が例）。

## 2. 作る順

### a. 画面

[`templates/demo.html`](../templates/demo.html) を複写して `{{ }}` を置き換える。雛形には学習の 6 段階（問い・予想・操作・比較・説明・転移）が印で入っている。段階を落とさない。

雛形は**今後の題材の複写元**という位置づけ。既存の k-means と 2D 座標変換はこれより先に作られており、雛形はその構造を写したもの。既存を組み直す必要は無い。

予想を選ばせる操作、段階的に開くヒント、語彙の切り替えはまだ入っていない（文章で促すだけ）。実装は別途行う。

深さが変わったら `../../` の数を直す。英語版は `lang="en"` にして `en/` 以下へ置き、互いの言語リンクを張る。

### b. 計算

計算は `js/` のライブラリに置き、画面側には置かない。

| 置き場所 | 入れるもの |
| --- | --- |
| `js/core/` | 乱数・数値の整形など、どの題材からも使うもの |
| `js/<分野>/` | その分野の計算（`linear-algebra`、`clustering` など） |
| `<題材名>/app.js` | 入力の読み取り、描画の呼び出し、文言の組み立て |

新しい分野を足すときは `js/<分野>/` を作り、`Readme.md` と `Readme.en.md` を必ず付ける。

守ること:

- **DOM と d3 に触らない。** そうすれば `node tests/run.js` から検証できる。
- 末尾は `})(typeof window !== "undefined" ? window : globalThis);` にする。Node からも読めるようになる。
- **乱数は呼び出し側から渡す。** `Math.random()` を直接使わない。同じ種で同じ結果にならなくなる。
- 0 で割る経路を残さない。`NaN` は図を黙って壊す。

### c. 文言

- **ページに固定で書ける文は HTML に直接書く。** 見出し・導入・確認事項など。
- **状態によって変わる文だけ** [`js/ui/i18n.js`](../js/ui/Readme.md) の辞書へ入れる。日英の両方に足す。

辞書に入れすぎると、HTML を読んでも何が表示されるか分からなくなる。

### d. 入力部品

```js
const pairs = JsDemo.Controls.bindPairs(["scale-x", "scale-y"], update);
```

id を `<name>` と `<name>-num` で揃えると、スライダーと数値入力が連動する。**どの値にも数値入力を必ず対にする。** 細かい操作が難しい場合やキーボードだけの場合でも同じ値に届くようにするため。

### e. 検証

`tests/cases.js` に照合を足す。

```js
test("分野名", "何を確かめるか", function () {
  near(実際, 期待, 許容誤差, "違ったときの説明");
});
```

既知値・境界値・不正入力・乱数の再現を入れる。**画面に絵が出たことを正確さの合格にしない。**

## 3. 公開前の確認

```bash
node tests/run.js              # 計算の照合。1 件でも落ちたら公開しない
node tools/check-links.js      # リンク切れと日英の対応
node tools/check-contrast.js   # 色のコントラスト比
node tools/check-controls.js   # スライダーと数値入力の範囲が揃っているか
node tools/check-transitions.js # 色をアニメーションさせていないか
python -m http.server 8000     # 実ブラウザで表示・操作を確認
```

あわせて [アクセシビリティ確認票](accessibility.md) を 1 題ずつ埋める。自動で測れないもの（キーボード操作・読み上げ・実機・投影）は人が確かめる。

## 4. 目録への登録

`index.html` と `en/index.html` の「デモ」一覧へカードを足す。題名・説明のほか、分野・対象・状態を書く。

図は各デモの中身が分かるものにする。トップページの図は座標を計算して組んである。

## 5. 依存を足すとき

外部ライブラリは**正確な版を指定する**（`d3@7.9.0`。`d3@7` のようなメジャー版指定にしない）。配信側の更新で挙動が変わる。

校内の通信制約で外部 CDN が届かない可能性がある。新しい依存を足す前に、本当に必要か確かめる。

## 6. 公開リポジトリに入れないもの

- 社内の企画・会議資料・試用記録・工数
- 学習者の氏名・回答・録画・成績などの個人情報
- 認証情報

内部資料は管理リポジトリ（private）側で扱う。
